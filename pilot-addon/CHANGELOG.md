# Changelog

## 0.9.3

- **Мастерская: пресеты LLM-платформ в онбординге** — в шаге «Супервизор»
  появился выбор платформы (DeepSeek, OpenAI, OpenRouter, GigaChat, YandexGPT,
  Mistral, Ollama). Пресет подставляет base_url и модель, вводить остаётся
  только API-ключ; при повторном открытии визарда платформа определяется по
  сохранённому адресу.

## 0.9.2

- **Мастерская: раздел «Модели» был пустым после онбординга** — он читал
  несуществующую секцию `models`, а визард пишет `supervisor`. Теперь раздел
  показывает секцию `supervisor` (base_url, модель, цены, расписание; ключ
  замаскирован). Каналы по-прежнему ждут своей реализации.

## 0.9.1

- **Исполнитель очереди доверия**: подтверждение «да» в очереди теперь реально
  исполняет действие в HA (раньше была заглушка, писавшая только в audit).
  Исполняемы только уставки `number.*`/`input_number.*` (запись через
  `*/set_value`, Supervisor-токен) и откат таких уставок; предложения
  супервизора без машинного действия подтверждаются как ack; всё прочее
  отказывается с записью в audit. Ошибка HA возвращает действие в очередь
  с пометкой «Не исполнено» — повтор только через подтверждение владельца
  (авто-применение вайтлистом для retry отключено). Setpoint-предложения
  супервизора теперь несут `previous` + `rollback_key` (откат одной правкой
  работает на уровне сущности, а не «supervisor»).
- **Статистика обучения**: очередь доверия считает решения владельца
  (предложено / принято / отклонено / применено молча) с разбивкой по виду
  действия; данные в `status.learning` (ws/HTTP). Раньше кнопка
  «Сброс обучения» обещала это, но серверной стороны не было — теперь сброс
  (`reset: learning`, и `reset: all`) реально очищает статистику. Это сырьё
  для адаптации персоны (Фаза 6), сама персона пока не меняется.
- **Checker: energy_spike оживлён** — флаг работал только как изолированный
  метод без источника данных. Теперь checker сам ведёт счётчики (сущности с
  `unit_of_measurement: kWh`/`Wh` из витрины): дневной прирост наращивается
  от первого сэмпла дня, при скачке >3× от медианы 14 дней флаг
  `energy_spike:<entity>`. Сброс счётчика (замена счётчика) — без флага.
- **Удалено WS-зеркало витрины** (`vitrine.py`): дублировало путь пушей от
  интеграции, в Supervisor-аддоне не запускалось, состояния не сохраняло.
  `py3-websockets` убран из образа; test-stand получает витрину через
  интеграцию (она смонтирована в HA).

## 0.9.0

- **Библиотека знаний** (раздел «Плагины» → «Библиотека»): системные промпты
  и навыки работают сразу (бандловые дефолты сидируются в `data/`), но
  редактируются в UI: редактор markdown, бейдж «правилось», сброс к дефолту.
  Новые ws-команды: `prompts/list|get|set|reset`, `skills/list|get|set|reset`
  (валидация slug, атомарная запись, audit без содержимого).
- Супервизор читает отредактированный системный промпт и навыки: секция
  «Навыки рантайма» в контексте запуска (≤16 КБ, обрезка с пометкой в
  журнале); правки применяются со следующего дневного run без перезапуска.
- Дефолтные навыки: `supervisor-home` (процедуры супервизора, вайтлист,
  формат журнала) и `home-domain` (шаблон доменных знаний дома —
  заполняется владельцем).

## 0.8.0

- **Онбординг-визард** (first-run): 4 шага — знакомство, настройка супервизора
  (провайдер, модель, ключ, лимит, время), пресет персоны, итог. Показывается,
  пока супервизор не настроен; доступен повторно по ссылке «Настройка».
- Новая ws-команда `config/set` (deep-merge секций в `pilot.json`, атомарная
  запись, битый конфиг бэкапится); флаг `onboarded` в `status`; audit-записи
  конфигурации без значений (ключи не утекают ни в логи, ни наружу).

## 0.7.0

- **LLM-супервизор** (дизайн 13.09): ежедневный запуск (07:00, конфигурируемо)
  над свежими флагами чекера. Один запуск на день; пустые флаги — 0 токенов.
  Уставки в пределах ±3 на number/input_number исполняются молча через HA API,
  всё остальное — в очередь доверия мастерской. Append-only журнал
  supervisor-log.md, учёт токенов и ₽ (прайсы в конфиге), budget-guard до
  запуска. Конфиг — секция `supervisor` в `pilot.json` (base_url, api_key,
  model, schedule, цены); без конфига запуски пропускаются мягко.
- Расширенный `status`: блок `supervisor` (last_run_ts, last_decisions,
  cost_today) — виден в мастерской.

## 0.6.1

- **Checker-слой оживлён**: периодические проверки отклонений по витрине
  (сенсоры протухли, климат без эффекта, свет горит сутки, импульсные реле
  застряли, энергопики) пишут флаги в статус и очередь доверия. Каждые
  5 минут витрина прогоняется через checker; флаг исчезает, как только
  условие ушло; каждый прогон записывается в аудит (`checker.run`).
- **Антиспам gate_stuck**: проверка «застрявшего реле» применяется только к
  сущностям, похожим на ворота/калитку/гараж (по id или имени) — обычные
  включённые приборы больше не дают флагов.
- **Дневной супервизор больше не дублирует предложения**: флаг, уже
  ожидающий подтверждения в очереди доверия, не предлагается повторно.

## 0.6.0

- **Раздел «Персона»**: шкалы (0–100) слайдерами, пресеты «Дворецкий» /
  «Тихий наблюдатель» / «Эконом» с индикатором отличия от пресета, лимит
  бюджета ₽/день, режим (Обычный/Отпуск/Гости/Болезнь). Новые ws-команды:
  `persona/set`, `preset/apply`, `budget/set`, `mode/set` — после каждой
  всем клиентам бродкастится свежий `status`.
- **Разделы «Каналы» / «Модели» / «Плагины»** (только чтение): обзор
  конфигурации рантайма из `pilot.json` через новую команду `config/get`;
  секреты (токены, ключи) маскируются сервером на `***`.
- **Разделы «Витрина» и «Очередь»** — перенесены из снятой нативной панели
  интеграции (см. 0.5.1): карта дома по комнатам со свежестью снапшота и
  очередь подтверждений контурa доверия.
- Заглушек в мастерской больше нет — все семь разделов живые.

## 0.5.0

- **Мастерская (SPA) за ingress**: аддон сам отдаёт собранный интерфейс
  администратора (Z2M-стиль) — кнопка «Открыть веб-интерфейс» в карточке
  аддона. Авторизация — сессия Home Assistant через Supervisor ingress,
  своя регистрация в аддоне не включается.
- **WebSocket-протокол `/ws`** для мастерской: команды `status`,
  `vitrine/get`, `queue/get`, `queue/confirm`, `logs/recent`,
  `logs/subscribe` / `logs/unsubscribe`. Ответы и события — JSON-фреймы
  `{type, payload}`; ошибка отвечает фреймом `error` и не разрывает
  соединение.
- **Ring-buffer логов** (5000 строк) в памяти рантайма: раздел «Админ»
  показывает live-логи по подписке и свежий хвост (`logs/recent`).
- **Статус слоёв рантайма** в ответе `status`: checker / vitrine / trust —
  жив ли слой и когда последний раз отрабатывал, плюс uptime аддона.
- Исходники мастерской живут внутри папки аддона (`pilot-addon/workshop/`) —
  образ собирается со SPA при любом способе сборки, в том числе при
  установке из магазина дополнений (Supervisor собирает из папки аддона).
- Собранный бандл (`pilot-addon/workshop/dist/`) закоммичен в git и просто
  копируется в образ — сборка образа не требует доступа к npm registry, что
  важно на медленных или нестабильных каналах. Актуальность бандла относительно
  исходников контролирует CI (джоба `workshop-bundle-check`).
- REST API интеграции (`/api/*`) не изменился.
