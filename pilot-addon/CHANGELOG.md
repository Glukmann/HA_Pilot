# Changelog

## 0.7.0

- **LLM-супервизор** (дизайн 13.09): ежедневный запуск (07:00, конфигурируемо)
  над свежими флагами чекера. Один запуск на день; пустые флаги — 0 токенов.
  Уставки в пределах ±3 на number/input_number исполняются молча через HA API,
  всё остальное — в очередь доверия мастерской. Append-only журнал
  supervisor-log.md, учёт токенов и ₽ (прайсы в конфиге), budget-guard до
  запуска. Конфиг — секция `supervisor` в `pilot.json` (base_url, api_key,
  model, schedule, цены); без конфига запуски пропускаются мягко.
- Расширенный `status`: блок `supervisor` (last_run_ts, last_decisions,
  cost_today) — виден в мастерской.

## 0.6.1

- **Checker-слой оживлён**: периодические проверки отклонений по витрине
  (сенсоры протухли, климат без эффекта, свет горит сутки, импульсные реле
  застряли, энергопики) пишут флаги в статус и очередь доверия. Каждые
  5 минут витрина прогоняется через checker; флаг исчезает, как только
  условие ушло; каждый прогон записывается в аудит (`checker.run`).
- **Антиспам gate_stuck**: проверка «застрявшего реле» применяется только к
  сущностям, похожим на ворота/калитку/гараж (по id или имени) — обычные
  включённые приборы больше не дают флагов.
- **Дневной супервизор больше не дублирует предложения**: флаг, уже
  ожидающий подтверждения в очереди доверия, не предлагается повторно.

## 0.6.0

- **Раздел «Персона»**: шкалы (0–100) слайдерами, пресеты «Дворецкий» /
  «Тихий наблюдатель» / «Эконом» с индикатором отличия от пресета, лимит
  бюджета ₽/день, режим (Обычный/Отпуск/Гости/Болезнь). Новые ws-команды:
  `persona/set`, `preset/apply`, `budget/set`, `mode/set` — после каждой
  всем клиентам бродкастится свежий `status`.
- **Разделы «Каналы» / «Модели» / «Плагины»** (только чтение): обзор
  конфигурации рантайма из `pilot.json` через новую команду `config/get`;
  секреты (токены, ключи) маскируются сервером на `***`.
- **Разделы «Витрина» и «Очередь»** — перенесены из снятой нативной панели
  интеграции (см. 0.5.1): карта дома по комнатам со свежестью снапшота и
  очередь подтверждений контурa доверия.
- Заглушек в мастерской больше нет — все семь разделов живые.

## 0.5.1

- **Единый пункт «Пилот» в боковом меню HA**: панель аддона переименована из
  «Мастерской» в «Пилот» (иконка `mdi:robot-outline`). Нативная панель
  интеграции снята с сайдбара — её функции (витрина дома, очередь
  подтверждений) переехали в разделы «Витрина» и «Очередь» самой мастерской.
  У пользователя один вход в продукт, дублей UI нет.

## 0.5.0

- **Мастерская (SPA) за ingress**: аддон сам отдаёт собранный интерфейс
  администратора (Z2M-стиль) — кнопка «Открыть веб-интерфейс» в карточке
  аддона. Авторизация — сессия Home Assistant через Supervisor ingress,
  своя регистрация в аддоне не включается.
- **WebSocket-протокол `/ws`** для мастерской: команды `status`,
  `vitrine/get`, `queue/get`, `queue/confirm`, `logs/recent`,
  `logs/subscribe` / `logs/unsubscribe`. Ответы и события — JSON-фреймы
  `{type, payload}`; ошибка отвечает фреймом `error` и не разрывает
  соединение.
- **Ring-buffer логов** (5000 строк) в памяти рантайма: раздел «Админ»
  показывает live-логи по подписке и свежий хвост (`logs/recent`).
- **Статус слоёв рантайма** в ответе `status`: checker / vitrine / trust —
  жив ли слой и когда последний раз отрабатывал, плюс uptime аддона.
- Исходники мастерской живут внутри папки аддона (`pilot-addon/workshop/`) —
  образ собирается со SPA при любом способе сборки, в том числе при
  установке из магазина дополнений (Supervisor собирает из папки аддона).
- Собранный бандл (`pilot-addon/workshop/dist/`) закоммичен в git и просто
  копируется в образ — сборка образа не требует доступа к npm registry, что
  важно на медленных или нестабильных каналах. Актуальность бандла относительно
  исходников контролирует CI (джоба `workshop-bundle-check`).
- REST API интеграции (`/api/*`) не изменился.
