# Changelog

## 0.14.0

- **Детерминированный fallback в чате** (цикл 1.5, `director.py`): простые
  просьбы разбираются без LLM — 0 токенов:
  «выключи/включи/переключи свет в <комнате>» → все светильники комнаты
  (каждое действие перепроверяет safety-классификатор);
  «какая температура в <комнате>?» → все °C-показания комнаты с именами,
  устройство-внутренние датчики (радио «5 ГГц», чипы) исключены, а при
  отсутствии датчика — честное «датчика нет» вместо подстановки похожего
  по имени (конец истории «41 °C в кабинете»);
  «поставь 22 [градуса] в <комнате>» → climate.set_temperature (ровно один
  климат в комнате, иначе — к LLM).
  Матчинг комнат стойкий к склонениям («в спальне» ↔ «Спальня»). Всё, что не
  распознано уверенно, идёт к модели как раньше; аудит помечает `chat.fallback`.

## 0.13.3

- Промпт чата: показатели самих устройств (нагрев радио «5 ГГц», CPU,
  аптайм, мощность розеток и т.п.) — не климат комнаты; при отсутствии
  подходящего датчика в комнате — честное «датчика нет» вместо подстановки
  ближайшего совпадения по названию (найдено тестированием: «температура
  в кабинете» = нагрев роутера 41 °C).

## 0.13.2

- **Память о владельце в чате** (цикл Б): в контекст хода добавляется
  «История решений хозяина» — итоги статистики (принято/отклонено, топ
  видов действий) и последние ~8 отказов из audit. Пилот учитывает привычки
  («в прошлый раз ты отклонил…»), а не предлагает то же по кругу.
- Интеграция 0.2.2 (цикл В): **детерминированный отчёт об исполнении** —
  после действий из чата в ответ всегда добавляется «Выполнено: <сущности>»
  по факту вызовов HA, независимо от того, что наговорила модель.

## 0.13.1

- **Статистика обучения и счётчик ₽/день переживают рестарт**: learning
  totals + разбивка по видам пишутся в `/data/learning.json`, расход —
  в `/data/cost.json` (атомарно, с днём-ключом; чужой день не подмешивается).
  Budget-guard теперь видит реальный расход сразу после старта.

## 0.13.0

- **Память диалога в чате** (цикл «агентности» А): последние 10 ходов
  разговора по conversation_id попадают в промпт — «а выключи тот же свет»
  работает. Сессии персистентны в `/data/chats/`, переживают рестарт и
  обновление; старые ходы отбрасываются по жёсткому потолку (бюджет).
- **Персона в чате**: системный промпт дополняется пресетом, шкалами
  (дворецкий/вежливость/осторожность), режимом дома и фокусом; слайдер
  болтливости управляет длиной ответов. Голос Пилота больше не одинаковый.
- `/api/chat` принимает `conversation_id`; интеграция 0.2.1 передаёт его из
  Assist.

## 0.12.2

- **Витрина показывает единицы измерения** (`Котёл Батарея: 96 %` вместо
  голого `96`): без единиц LLM путал заряд батарейки датчика с температурой
  («96 градусов» по факту процента). Плюс правило в промпте чата: значения
  с `%` и сущности вида «…Батарея/…Влажность» не температуры устройства.

## 0.12.1

- **Чат и супервизор видели не весь дом**: контекст витрины обрезался до
  последних 120 строк — у большого дома часть сущностей не попадала в
  промпт и LLM о них не знал. Лимит поднят до 300 строк (≈4–5k токенов
  ввода — копейки на фоне цены запроса), при обрезке в промпт добавляется
  пометка, что показан хвост.

## 0.12.0

  - **Персистентная очередь доверия** (`/data/queue.json`): предложения,

## 0.11.0

- **Чат-пульт (Assist)**: новый `POST /api/chat` — один диалоговый ход в
  активный профиль модели: системный промпт Пилота + витрина как контекст,
  строгий JSON-ответ `{"say", "actions"}`, общий budget-guard (₽/день с
  супервизором), cost-учёт. Действия классифицирует детерминированный
  `safety.py`: direct (свет, медиа, уставки ±3, …) исполняет интеграция
  через HA services; queue (switch, ворота/двери, незнакомое) — предложение
  в очередь доверия; refuse (камеры, охрана, замки) — никогда. Новый
  `POST /api/queue` для постановки предложений в очередь.
- Интеграция 0.2.0: `ConversationEntity` «Pilot» — Пилот третьим агентом в
  Assist (рядом со встроенным и Ollama); можно назначить preferred-агентом
  и общаться только с ним. Обратимое исполняет мгновенно, необратимое —
  «ждёт подтверждения в мастерской».

## 0.10.0

- **Модели: несколько профилей с выбором активного** (раздел перестал быть

- UI: раздел «Модели» — список профилей с бейджами (активна / ключ
  сохранён / нет ключа), форма добавления/правки с пресетами платформ.

## 0.9.1

- **Исполнитель очереди доверия**: подтверждение «да» в очереди теперь реально
  исполняет действие в HA (раньше была заглушка, писавшая только в audit).
  Исполняемы только уставки `number.*`/`input_number.*` (запись через
  `*/set_value`, Supervisor-токен) и откат таких уставок; предложения
  супервизора без машинного действия подтверждаются как ack; всё прочее
  отказывается с записью в audit. Ошибка HA возвращает действие в очередь
  с пометкой «Не исполнено» — повтор только через подтверждение владельца
  (авто-применение вайтлистом для retry отключено). Setpoint-предложения
  супервизора теперь несут `previous` + `rollback_key` (откат одной правкой
  работает на уровне сущности, а не «supervisor»).
- **Статистика обучения**: очередь доверия считает решения владельца
  (предложено / принято / отклонено / применено молча) с разбивкой по виду
  действия; данные в `status.learning` (ws/HTTP). Раньше кнопка
  «Сброс обучения» обещала это, но серверной стороны не было — теперь сброс
  (`reset: learning`, и `reset: all`) реально очищает статистику. Это сырьё
  для адаптации персоны (Фаза 6), сама персона пока не меняется.
- **Checker: energy_spike оживлён** — флаг работал только как изолированный
  метод без источника данных. Теперь checker сам ведёт счётчики (сущности с
  `unit_of_measurement: kWh`/`Wh` из витрины): дневной прирост наращивается
  от первого сэмпла дня, при скачке >3× от медианы 14 дней флаг
  `energy_spike:<entity>`. Сброс счётчика (замена счётчика) — без флага.
- **Удалено WS-зеркало витрины** (`vitrine.py`): дублировало путь пушей от
  интеграции, в Supervisor-аддоне не запускалось, состояния не сохраняло.
  `py3-websockets` убран из образа; test-stand получает витрину через
  интеграцию (она смонтирована в HA).

  ожидающий подтверждения в очереди доверия, не предлагается повторно.

## 0.5.0

- **Мастерская (SPA) за ingress**: аддон сам отдаёт собранный интерфейс
  администратора (Z2M-стиль) — кнопка «Открыть веб-интерфейс» в карточке
  аддона. Авторизация — сессия Home Assistant через Supervisor ingress,
  своя регистрация в аддоне не включается.
- **WebSocket-протокол `/ws`** для мастерской: команды `status`,
  `vitrine/get`, `queue/get`, `queue/confirm`, `logs/recent`,
  `logs/subscribe` / `logs/unsubscribe`. Ответы и события — JSON-фреймы
  `{type, payload}`; ошибка отвечает фреймом `error` и не разрывает
  соединение.
- **Ring-buffer логов** (5000 строк) в памяти рантайма: раздел «Админ»
  показывает live-логи по подписке и свежий хвост (`logs/recent`).
- **Статус слоёв рантайма** в ответе `status`: checker / vitrine / trust —
  жив ли слой и когда последний раз отрабатывал, плюс uptime аддона.
- Исходники мастерской живут внутри папки аддона (`pilot-addon/workshop/`) —
  образ собирается со SPA при любом способе сборки, в том числе при
  установке из магазина дополнений (Supervisor собирает из папки аддона).
- Собранный бандл (`pilot-addon/workshop/dist/`) закоммичен в git и просто
  копируется в образ — сборка образа не требует доступа к npm registry, что
  важно на медленных или нестабильных каналах. Актуальность бандла относительно
  исходников контролирует CI (джоба `workshop-bundle-check`).
- REST API интеграции (`/api/*`) не изменился.
