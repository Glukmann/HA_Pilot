# Супервизор дома

Процедуры одного дневного запуска (1×/день, детерминированный checker уже
вычислил флаги отклонений).

## Порядок запуска

1. **Budget-guard**: дневной лимит исчерпан (`cost_today >= daily_budget`) —
   не запускаться, короткая запись в журнал.
2. **Свежесть флагов**: доверять только свежим (checker отрабатывал меньше
   12 ч назад). Протухшие флаги — запись «флаги протухли», выход.
3. **Пустой день**: флагов нет — короткая запись «всё в норме», LLM не
   вызывать (0 токенов).
4. **Рабочий день**: прочитать флаги, карту дома (витрину), текущие уставки
   и хвост журнала → решить → исполнить молчаливое или поставить на
   подтверждение → дописать журнал.

## Вайтлист молчаливых правок

- Только `number.*` / `input_number.*` и только в пределах **±3** от текущего
  значения — исполнение через HA API без подтверждения.
- Всё остальное — предложение в очередь доверия; исполняет только владелец.
- Ворота, реле, выключатели, автоматизации, камеры, медиа — **никогда** молча.
- Исполнение не удалось — то же решение уходит в очередь с пометкой об ошибке.

## Формат записи в supervisor-log.md

Каждый запуск заканчивается записью (append-only):

    ## <дата> <время> (Supervisor: дом)
    Вход: флаги [...] | snap 🟢/🔴
    Решение: <короткий вывод>
    Изменено: <entity_id> <old>→<new>
    Стоимость: <tok in> / <tok out> ≈ ₽<сумма> (<модель>)
    Итог: <n> правок молча, <m> на подтверждении

Тихий день — сокращённая запись с «всё в норме». Ответ «что ты менял за
неделю?» = `grep "^## " supervisor-log.md` + чтение записей.

## Budget-guard и учёт

- Лимит жёсткий (по умолчанию ₽10/день); упёрлись — запуск отменяется.
- Каждая копейка видна: токены и стоимость идут в журнал и в `status`
  (`supervisor.cost_today`); при смене суток счётчик обнуляется.
